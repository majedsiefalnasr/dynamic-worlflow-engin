# خطة التسليم ومعايير القبول

الترتيب إلزامي. لا يبدأ ربط مرحلة تعتمد على مرحلة سابقة قبل ثبات عقود السابقة.

## المرحلة 1: الجهات

Backend:

- migration, model, policy, requests, resources, CRUD APIs.
- seed للجهات الافتراضية المحمية.

UI:

- ربط `/admin/orgs`.
- إزالة اعتماد الشاشة على `orgsCell`.

القبول:

- إضافة جهة مخصصة.
- منع حذف الافتراضية.
- منع تعطيل جهة مستخدمة.

## المرحلة 2: الفرق

- تعتمد على الجهات.
- ربط `/admin/teams`.
- إثبات أن الفريق يتبع جهة واحدة ولا يحمل دورًا ثابتًا.

## المرحلة 3: الأدوار

- تعتمد على الجهات.
- ربط `/admin/roles`.
- منع حذف أو تعطيل دور مستخدم.

## المرحلة 4: البنوك

- تعتمد على جهة البنوك التجارية.
- ربط `/admin/entities` بوصفها شاشة البنوك.
- منع تعطيل بنك مستخدم.

## المرحلة 5: المستخدمون والمصادقة

- تعتمد على الجهات والفرق والأدوار والبنوك.
- JWT + MFA + `/auth/me`.
- ربط `/admin/cby-staff` و`/bank/users`.
- حذف login demo وRoleSwitcher عند اكتمال الربط.

## المرحلة 6: إدارة التجار

- تعتمد على البنوك والمستخدمين والبيانات الأساسية المستخدمة للقطاع.
- ربط `/merchants`.
- دعم الملاك والشركات المرتبطة والنطاق البنكي.

## المرحلة 7: مصمم سير العمل

ترتيب داخلي:

1. definitions وversions.
2. stages.
3. actions.
4. transitions.
5. stage permissions.
6. field groups وfields.
7. stage field rules.
8. validate/publish.
9. graph.

ربط `/admin/workflows`.

القبول:

- لا تعديل على published.
- clone ينتج draft مستقلًا.
- validate يشرح كل خطأ.
- publish يرفض التكوين غير الصالح.

## المرحلة 8: الطلبات

- إنشاء طلب من النسخة النشطة.
- عرض التفاصيل والحقول والملفات والتاريخ.
- حفظ مسودة وتنفيذ انتقال بتزامن آمن.
- ربط `/workflows` و`/workflows/instances/$id`.

## المرحلة 9: طابور «دوري»

- endpoint مستقل مشتق من المرحلة الحالية وصلاحيات التنفيذ.
- تحديث فوري بعد الانتقال عبر invalidation أو refetch.

## المرحلة 10: التدقيق والامتثال

- audit append-only.
- ربط `/audit`.
- إزالة الأرقام ومؤشرات المخاطر الوهمية.

## المرحلة 11: التقارير والتحليلات

- APIs مجمعة وتطبيق نطاق المستخدم.
- Excel وPDF.
- ربط `/reports`.
- إزالة `MONTHLY` و`CATEGORY_DIST`.

## المرحلة 12: البيانات الأساسية

- ربط `/admin/reference-data`.
- حماية الجداول والقيم المستخدمة.

ملاحظة اعتماد: يمكن تنفيذ foundation البيانات الأساسية مبكرًا إذا احتاجها التجار أو حقول المصمم، لكن تسليم الشاشة يبقى في هذا الموضع حسب الأولوية.

## المرحلة 13: صلاحيات الشاشات

- كتالوج كامل للشاشات والقدرات.
- ربط `/admin/screen-permissions`.
- استبدال `RoleGuard` المبني على role codes بصلاحيات backend.

## المرحلة 14: الإشعارات

- إشعارات per-user مع القراءة والأرشفة.
- queue jobs لأحداث سير العمل وSLA.
- ربط `/notifications` وعداد الرأس.

## بوابة كل مرحلة

- OpenAPI محدث.
- Feature tests ناجحة.
- Postman أو Swagger قابل للتجربة.
- بيانات seed دنيا وليست demo business data.
- لا breaking change غير موثق.
- UI مربوط ومختبر.
- audit والصلاحيات مطبقة.
